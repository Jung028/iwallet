## Module Structure

The project is a multi-module Maven project built on **SOFABoot**. The top-level modules are:

| Module | Path | Responsibility |
|--------|------|----------------|
| `bootstrap` | `app/bootstrap` | Application startup and Spring Boot entry point |
| `web` | `app/web` | HTTP/REST controllers (API gateway) |
| `biz/service/impl` | `app/biz/service/impl` | Business service implementations, templates, handlers, checkers |
| `biz/shared` | `app/biz/shared` | Shared business logic across biz modules |
| `common/service/facade` | `app/common/service/facade` | Service interfaces (contracts), request/response DTOs, enums |
| `common/service/integration` | `app/common/service/integration` | Integration with external services |
| `common/dal` | `app/common/dal` | DAOs, DOs, and MyBatis XML mappers |
| `common/util` | `app/common/util` | Shared utilities, enums, event helpers |
| `core/model` | `app/core/model` | Domain objects, converters, core enums, events, exceptions, AssertUtil |
| `core/service` | `app/core/service` | Repository interfaces and their implementations |
| `test` | `app/test` | Integration and unit tests |

## Dependency Flow

```
app/web
  └─► app/biz/service/impl
        └─► app/core/service          (repository layer)
              └─► app/core/model      (domain objects, converters, AssertUtil)
              └─► app/common/dal      (DAOs + DOs + mappers)
        └─► app/common/service/facade (service interfaces + DTOs)
        └─► app/common/util           (shared utilities, enums, events)
```

Higher-level modules depend on lower-level ones. The `facade` module is the public contract — its interfaces are what callers depend on.

## Data Object (DO) Layer

**Location:** `app/common/dal/src/main/java/com/alipay/business/common/dal/auto/dataobject/`  
**Package:** `com.alipay.business.common.dal.auto.dataobject`

DOs are plain Java classes generated by **MyBatis Generator**. They map 1:1 to database table columns (snake_case columns → camelCase fields).

**Convention:**
- Suffix: `DO` (e.g., `QrCodeDO`, `IdempotencyKeysDO`)
- No business logic — pure data holders
- Fields mirror DB column names exactly

**Example — `QrCodeDO`:**
```java
// app/common/dal/.../dataobject/QrCodeDO.java
public class QrCodeDO {
    private String qrId;
    private String ownerId;
    private String ownerType;
    private String intent;
    private BigDecimal amount;
    private String currency;
    private String status;
    private String signature;
    private Date expiresAt;
    private Date createdAt;
    private Date updatedAt;
    // getters/setters ...
}
```

**Example — `IdempotencyKeysDO`:**
```java
// app/common/dal/.../dataobject/IdempotencyKeysDO.java
public class IdempotencyKeysDO {
    private Long id;
    private String idempotencyKey;
    private String userId;
    private String requestHash;
    private String referenceId;
    private String status;
    private String errorCode;
    private String responseSnapshot;
    private Date createdAt;
    private Date updatedAt;
    private Integer retryCount;
    private String idempotencyType;
}
```

## DAO Layer

**Location:** `app/common/dal/src/main/java/com/alipay/business/common/dal/auto/custom/`  
**Package:** `com.alipay.business.common.dal.auto.custom`

DAOs are MyBatis mapper interfaces annotated with `@Mapper`. They accept and return DOs. Use `@Param` for multi-argument methods.

**Convention:**
- Suffix: `DAO` (e.g., `QrCodeDAO`, `IdempotencyKeysDAO`)
- Annotated with `@Mapper`
- Methods operate on `*DO` types only — no domain objects leak into this layer

**Example — `QrCodeDAO`:**
```java
// app/common/dal/.../custom/QrCodeDAO.java
@Mapper
public interface QrCodeDAO {
    int insertQrCode(QrCodeDO qrCodeDO);
}
```

**Example — `IdempotencyKeysDAO`:**
```java
// app/common/dal/.../custom/IdempotencyKeysDAO.java
@Mapper
public interface IdempotencyKeysDAO {
    IdempotencyKeysDO queryIdempotencyKeysByIdempotencyKey(
        @Param("idempotencyKey") String idempotencyKey
    );
    int updateIdempotencyKeys(IdempotencyKeysDO idempotencyKeysDO);
    int insertIdempotencyKey(IdempotencyKeysDO idempotencyKeysDO);
}
```

## MyBatis Mapper / Database Setup

**Auto-generated mappers:** `app/common/dal/src/main/resources/sqlmap/iwallet/auto/`  
**Custom mappers:** `app/common/dal/src/main/resources/mapper/custom/`

Each DAO interface has a corresponding XML mapper. The custom mapper namespace must match the fully qualified DAO interface name.

**Example — `QrCode-sqlmap-mapping.xml`:**
```xml
<mapper namespace="com.alipay.business.common.dal.auto.custom.QrCodeDAO">

    <resultMap id="BaseResultMap" type="com.alipay.business.common.dal.auto.dataobject.QrCodeDO">
        <id     column="qr_id"      jdbcType="VARCHAR" property="qrId"      />
        <result column="owner_id"   jdbcType="VARCHAR" property="ownerId"   />
        <result column="owner_type" jdbcType="VARCHAR" property="ownerType" />
        <result column="amount"     jdbcType="DECIMAL" property="amount"    />
        <result column="currency"   jdbcType="VARCHAR" property="currency"  />
        <result column="status"     jdbcType="VARCHAR" property="status"    />
        <result column="created_at" jdbcType="TIMESTAMP" property="createdAt" />
        <result column="updated_at" jdbcType="TIMESTAMP" property="updatedAt" />
    </resultMap>

    <insert id="insertQrCode" parameterType="com.alipay.business.common.dal.auto.dataobject.QrCodeDO">
        INSERT INTO qr_code (qr_id, owner_id, owner_type, amount, currency, status, created_at, updated_at)
        VALUES (#{qrId}, #{ownerId}, #{ownerType}, #{amount}, #{currency}, #{status}, #{createdAt}, #{updatedAt})
    </insert>

</mapper>
```

**Adding a new table checklist:**
1. Create the `*DO` class in `common/dal/.../dataobject/`
2. Create the `*DAO` interface (annotated `@Mapper`) in `common/dal/.../custom/`
3. Create the XML mapper in `common/dal/src/main/resources/mapper/custom/`
4. Register the mapper XML path in MyBatis config if needed

## Domain Model Layer

**Location:** `app/core/model/src/main/java/com/alipay/business/core/model/domain/`  
**Package:** `com.alipay.business.core.model.domain`

Domain objects are the business representation of data — separate from the DB layer. They can carry business logic.

**Convention:**
- No suffix (e.g., `QrCode`, `IdempotencyKeys`)
- Structurally similar to the corresponding DO, but decoupled
- Never passed into DAOs

**Example — `QrCode`:**
```java

    private String currency;
    private String status;
    private String signature;
    private Date expiresAt;
    private Date createdAt;
    private Date updatedAt;
    // getters/setters ...
}
```

## DO ↔ Domain Conversion

**Location:** `app/core/model/src/main/java/com/alipay/business/core/model/converter/`  
**Package:** `com.alipay.business.core.model.converter`

There are two converter patterns used in this project:

### 1. Static Convertor (per-entity, one-way)

Used for simpler or one-way conversions. Named `*Convertor` (note the spelling).

```java
// app/core/model/.../converter/QrCodeConvertor.java
public class QrCodeConvertor {
    public static QrCodeDO convertToDO(QrCode qrCode) {
        QrCodeDO qrCodeDO = new QrCodeDO();
        qrCodeDO.setQrId(qrCode.getQrId());
        qrCodeDO.setAmount(qrCode.getAmount());
        qrCodeDO.setCurrency(qrCode.getCurrency());
        // ... more field mappings
        return qrCodeDO;
    }
}
```

### 2. `ModelConverter` (Spring bean, bidirectional)

A `@Component` bean that handles both directions. Inject it wherever bidirectional conversion is needed (typically in repository implementations).

```java
// app/core/model/.../converter/ModelConverter.java
@Component
public class ModelConverter {

    public IdempotencyKeys convertToModel(IdempotencyKeysDO do) {
        if (do == null) return null;
        IdempotencyKeys model = new IdempotencyKeys();
        model.setId(do.getId());
        model.setIdempotencyKey(do.getIdempotencyKey());
        // ... field mappings
        return model;
    }

    public IdempotencyKeysDO convertToDO(IdempotencyKeys model) {
        if (model == null) return null;
        IdempotencyKeysDO do = new IdempotencyKeysDO();
        do.setId(model.getId());
        // ... field mappings
        return do;
    }
}
```

**Rule:** All field mappings are explicit (no reflection-based copy). This makes refactors safe and compilation errors visible.

## Repository Layer

**Interfaces:** `app/core/service/src/main/java/com/alipay/business/core/service/`  
**Implementations:** `app/core/service/src/main/java/com/alipay/business/core/service/repository/`  
**Packages:** `com.alipay.business.core.service` / `com.alipay.business.core.service.repository`

The repository bridges the domain layer and the DAO layer. It accepts and returns **domain objects** — never DOs. Conversion happens inside the repository.

**Convention:**
- Interface suffix: `Repository` (e.g., `QrCodeRepository`)
- Implementation suffix: `RepositoryImpl` (e.g., `QrCodeRepositoryImpl`)
- Both annotated with `@Repository`
- Inject the DAO with `@Autowired`
- Inject `ModelConverter` with `@Autowired` for DO ↔ domain conversion

**Example — `QrCodeRepository` interface:**
```java
// app/core/service/.../QrCodeRepository.java
@Repository
public interface QrCodeRepository {
    void insertQrCode(QrCode qrCode);
    void updateQrCode(String qrId, String status);
}
```

**Example — `QrCodeRepositoryImpl`:**
```java
// app/core/service/.../repository/QrCodeRepositoryImpl.java
@Repository
public class QrCodeRepositoryImpl implements QrCodeRepository {

    @Autowired
    private QrCodeDAO qrCodeDAO;

    @Override
    public void insertQrCode(QrCode qrCode) {
        QrCodeDO qrCodeDO = QrCodeConvertor.convertToDO(qrCode);
        qrCodeDAO.insertQrCode(qrCodeDO);
    }

    @Override
    public void updateQrCode(String qrId, String status) {
        qrCodeDAO.updateQrCode(qrId, status);
    }
}
```

**Example — `IdempotencyKeysRepositoryImpl` (uses `ModelConverter`):**
```java
// app/core/service/.../repository/IdempotencyKeysRepositoryImpl.java
@Repository
public class IdempotencyKeysRepositoryImpl implements IdempotencyKeysRepository {

    @Autowired
    protected IdempotencyKeysDAO idempotencyKeysDAO;

    @Autowired
    protected ModelConverter modelConverter;

    public IdempotencyKeys queryByKey(String key) {
        IdempotencyKeysDO doObj = idempotencyKeysDAO.queryIdempotencyKeysByIdempotencyKey(key);
        return modelConverter.convertToModel(doObj);
    }
}
```

**Adding a new repository checklist:**
1. Define the interface in `core/service/.../core/service/`
2. Create the implementation in `core/service/.../core/service/repository/`
3. Inject the corresponding `*DAO` and (if needed) `ModelConverter`
4. Never let DOs escape the repository — always convert before returning

## Service Layer (Facade & Implementation)

### Service Interface (Facade)

**Location:** `app/common/service/facade/src/main/java/com/alipay/business/common/service/facade/api/`  
**Package:** `com.alipay.business.common.service.facade.api`

Interfaces use JAX-RS annotations for REST exposure via SOFA.

```java
// app/common/service/facade/.../api/QrCodeService.java
@Path("/qrCodeService")
@Produces(MediaType.APPLICATION_JSON)
@Consumes(MediaType.APPLICATION_JSON)
public interface QrCodeService {
    BusinessBizResult<String> generateQrCode(GenerateQrCodeRequest request);
}
```

### Service Implementation

**Location:** `app/biz/service/impl/src/main/java/com/alipay/business/biz/service/impl/business/impl/`  
**Package:** `com.alipay.business.biz.service.impl.business.impl`

Implementations use both `@SofaService` (for SOFA binding) and `@Service` (for Spring).

```java
// app/biz/service/impl/.../impl/QrCodeServiceImpl.java
@SofaService(
    interfaceType = QrCodeService.class,
    bindings = {
        @SofaServiceBinding(bindingType = "rest"),
        @SofaServiceBinding(bindingType = "bolt")
    }
)
@Service
public class QrCodeServiceImpl extends AbstractBusinessBizService implements QrCodeService {

    @Override
    public BusinessBizResult<String> generateQrCode(GenerateQrCodeRequest request) {
        return businessServiceTemplate.execute(
            request,
            BusinessActionEnum.GENERATE_QR_CODE,
            new BusinessBizCallback<>() {
                @Override
                public void checkParams(GenerateQrCodeRequest req) {
                    BusinessRequestChecker.checkGenerateQrCodeRequest(req);
                }

                @Override
                public BusinessBizResult<String> process(GenerateQrCodeRequest req) {
                    // business logic here
                }
            }
        );
    }
}
```

## Service Template Pattern

**Location:** `app/biz/service/impl/src/main/java/com/alipay/business/biz/service/impl/template/`

All service method implementations go through `BusinessServiceTemplate.execute()`. This template provides a consistent pipeline:

1. Validate params (via `callback.checkParams()`)
2. Initialize context
3. Execute business logic (via `callback.process()`)
4. Handle and wrap exceptions uniformly

```java
// Usage pattern in any service impl:
return businessServiceTemplate.execute(request, BusinessActionEnum.SOME_ACTION,
    new BusinessBizCallback<ResponseType>() {

        @Override
        public void checkParams(RequestType req) {
            BusinessRequestChecker.checkSomeRequest(req);
        }

        @Override
        public BusinessBizResult<ResponseType> process(RequestType req) {
            // core logic
        }
    }
);
```

**`BusinessBizCallback` abstract methods:**
- `checkParams(T request)` — throw on invalid input
- `process(T request)` — return the result
- `createDefaultResponse()` — fallback on error

## Publisher / Subscriber (Event Pattern)

**Event classes (facade):** `app/common/service/facade/src/main/java/com/alipay/business/common/service/facade/event/`  
**Event classes (core):** `app/core/model/src/main/java/com/alipay/business/core/model/event/`  
**Event utilities:** `app/common/util/src/main/java/com/alipay/business/common/util/`

Events are plain POJOs. Use `EventContext` and `EventContextUtil` to carry event metadata.

**Event POJO example — `EcTopUpEvent`:**
```java

public class EcTopUpEvent {

    private BigDecimal amount;

    private String paymentIntentId;

    private Date gmtTaskOccur;
    // getters/setters

```

**Event POJO example — `EcTransactionEvent`:**
```java
// app/core/model/.../event/EcTransactionEvent.java
public class EcTransactionEvent {
    private String transactionId;
    private String payeeAccountId;
    private String payerAccountId;
```

**Event location rule:**
- Events tied to a specific facade operation → `common/service/facade/.../event/`
- Events representing internal domain transitions → `core/model/.../event/`

Use `EventContextUtil` to attach/retrieve context when publishing or consuming events.

## AssertUtil

**Location:** `app/core/model/src/main/java/com/alipay/business/core/model/util/AssertUtil.java`  
**Package:** `com.alipay.business.core.model.util`

`AssertUtil` provides guard-clause style validation. On failure it throws `BaseSlipException` with the given result code and message, stopping execution immediately.

**Available methods:**

| Method | Throws when |
|--------|------------|
| `AssertUtil.notNull(value, resultCode, message)` | `value == null` |
| `AssertUtil.notBlank(value, resultCode, message)` | `value` is null or blank |
| `AssertUtil.isTrue(condition, resultCode, message)` | `condition == false` |
| `AssertUtil.notEmpty(list, resultCode, message)` | `list` is null or empty |

**Usage — always use in checker or early in service logic:**

```java
AssertUtil.notNull(request,                   BusinessResultCode.PARAM_ILLEGAL, "request is null");
AssertUtil.notBlank(request.getUniqueRequestId(), BusinessResultCode.PARAM_ILLEGAL, "uniqueRequestId is blank");
AssertUtil.notBlank(request.getPayeeAccountNo(),  BusinessResultCode.PARAM_ILLEGAL, "payeeAccountNo is blank");
AssertUtil.notNull(request.getAmount(),           BusinessResultCode.PARAM_ILLEGAL, "amount is null");
AssertUtil.isTrue(request.getAmount().compareTo(BigDecimal.ZERO) > 0,
                  BusinessResultCode.PARAM_ILLEGAL, "amount must be positive");
```

## Request Validation (Checker Pattern)

**Location:** `app/biz/service/impl/src/main/java/com/alipay/business/biz/service/impl/checker/`  
**Package:** `com.alipay.business.biz.service.impl.checker`

All input validation is centralized in static checker classes. Each service has a corresponding checker method. Checkers use `AssertUtil` exclusively.

```java
// app/biz/service/impl/.../checker/BusinessRequestChecker.java
public class BusinessRequestChecker {

    public static void checkTransferRequest(TransferRequest request) {
        AssertUtil.notNull(request,                        BusinessResultCode.PARAM_ILLEGAL, "request is null");
        AssertUtil.notBlank(request.getUniqueRequestId(),  BusinessResultCode.PARAM_ILLEGAL, "uniqueRequestId is null");
        AssertUtil.notBlank(request.getPayeeAccountNo(),   BusinessResultCode.PARAM_ILLEGAL, "payeeAccountNo is null");
        AssertUtil.notNull(request.getAmount(),            BusinessResultCode.PARAM_ILLEGAL, "amount is null");
    }

    public static void checkGenerateQrCodeRequest(GenerateQrCodeRequest request) {
        AssertUtil.notNull(request, BusinessResultCode.PARAM_ILLEGAL, "request is null");
        // ... other checks
    }
}
```

**Rule:** Never inline `if (x == null) throw ...` in service implementations. Always delegate to a checker method that uses `AssertUtil`.

## Quick Reference — Adding a New Feature End-to-End

1. **DB schema** — Add table/column, create or update the XML mapper in `common/dal/src/main/resources/mapper/custom/`
2. **DO** — Create `MyEntityDO` in `common/dal/.../dataobject/`
3. **DAO** — Create `MyEntityDAO` (`@Mapper`) in `common/dal/.../custom/`
4. **Domain model** — Create `MyEntity` in `core/model/.../domain/`
5. **Converter** — Add conversion methods to `ModelConverter` (or create a static `MyEntityConvertor`)
6. **Repository interface** — Define `MyEntityRepository` in `core/service/...`
7. **Repository impl** — Create `MyEntityRepositoryImpl` in `core/service/.../repository/`, inject DAO + converter
8. **Enums** — Add to the appropriate `enums` package based on which module owns the concept
9. **Request/Response DTOs** — Add to `common/service/facade/.../request/` and `.../result/`
10. **Service interface** — Add method to the relevant interface in `common/service/facade/.../api/`
11. **Checker** — Add a `checkMyRequest()` static method in `biz/service/impl/.../checker/BusinessRequestChecker.java`
12. **Service impl** — Implement the method in the relevant `*ServiceImpl`, wrapping with `businessServiceTemplate.execute()` and calling the checker in `checkParams()`
